# Nagi macOS menu app

The macOS 13+ app lives only in the menu bar. It opens no main window and has no Dock icon. The native menu shows engine status, system proxy and TUN controls, runtime mode, selectable proxy groups, profiles, subscriptions, display choices, startup choices, Help, About, and Quit. Under Profiles, the `default` submenu can select the default profile or apply its safe local runtime settings to the current profile through `profile override apply-default NAME`; proxy nodes, groups, rules, and Nagi-managed fields are excluded. It starts Nagi on launch, accepts an already running engine, and keeps the menu available if startup fails so Retry Start can be used. Quit runs the CLI cleanup command before the app terminates; a failed cleanup leaves the menu open with the CLI error.

Install the matching Nagi CLI as an executable at `/usr/local/bin/nagi`. Install the pinned mihomo executable beside the CLI, or provide `NAGI_MIHOMO_BIN` in the app's environment. For a local build, [install from an artifact directory](../../docs/development/install.md), optionally including `Nagi.app` (installed to `/Applications/Nagi.app` by default). The app invokes only `nagi --json` commands; it does not read Nagi configuration files or contact mihomo's socket or API. The [CLI reference](../../docs/reference/cli.md) defines commands and JSON fields.

The `default` submenu uses Nagi's built-in configuration template, which installation and updates replace with the installed version's defaults. Use another name for personal profiles and subscriptions; see the [installation workflow](../../docs/development/install.md#install-update-and-remove).

The default macOS installer configures the privileged CLI backend for TUN; see [traffic access](../../docs/guides/traffic-access.md). The app uses the selected backend through the same CLI commands, so changing backends does not require rebuilding the app.

The status item uses Apple's native `network.badge.shield.half.filled` geometry in white. Starting, stopped, and unavailable draw the whole symbol at half opacity; running draws it at full opacity. While applying a setting, the network globe stays fully opaque and only the shield alternates between half and full opacity. The item also displays mihomo's upload and download rates once a second from `nagi --json traffic watch`. Traffic rates is the default Display choice, with the icon vertically centered beside two right-aligned rate rows at fixed width and no arrows; Icon only is the other choice. The numeric display uses a monospaced font. A missing or stale sample, or a stopped engine, displays `0 B/s` for each visible rate. A saved Download only choice falls back to Traffic rates. The app reconnects the stream after interruption while the engine is running. Display choice is the only app data stored in UserDefaults.

While a menu command is applying a setting, the shield animates and the menu is temporarily detached so it cannot be opened. The app uses the command result to update mode, proxy selection, TUN, system proxy, and login service state without waiting for a full menu refresh. Profile selection and subscription application refresh the affected profile and runtime controls before the menu is available again. Periodic and menu-open refreshes still reconcile the displayed state. The animation stops when the command and any required targeted refresh finish or report an error.

The status menu item shows `Nagi · Running ⚠` when the engine is running and an error is present. Its submenu shows the error details while keeping the engine state visible. The Subscriptions menu offers Download Subscription… to prompt for a name and URL, save the subscription, and download and validate its cache without activating it. If the download fails, the saved record remains so it can be retried. Each saved subscription offers Apply to activate its cached content without downloading, Update and Apply to download and then activate it, and Delete Subscription to remove its record and cache after confirmation. Apply requires a cache; if none exists, the CLI reports an error. Deleting a subscription leaves any previously applied profile intact. If applying after an update fails, the updated cache remains available and the error states that activation failed. Mihomo Selector groups offer clickable node choices. Automatic groups show their current result and members as read-only menu items; groups with no members show an explicit message. A TUN setting can be on while its adapter is absent or down; the menu shows that warning. Under “Login,” “Run engine at login” installs or uninstalls the CLI's login service; uninstalling removes its service definition and leaves profiles and settings intact. “Open menu bar app at login” uses macOS `SMAppService` and requires an installed app bundle.

Build and package on macOS with Xcode command line tools:

```sh
make build app
open bin/Nagi.app
```

`make build app` calls the packaging script on macOS and creates `bin/Nagi.app` with `LSUIElement` set to true. You can also run `macos/NagiApp/package-app.sh` directly to rebuild only the App bundle. SwiftPM alone builds an executable, not an app bundle with the menu-only activation setting. Install the built app in Applications before enabling its login item; include the bundle in the [artifact directory](../../docs/development/install.md) to install it alongside the CLI. The app is not signed or notarized by this script, and the repository release script does not package it.
